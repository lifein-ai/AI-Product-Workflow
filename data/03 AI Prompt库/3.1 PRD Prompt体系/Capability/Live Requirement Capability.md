# Live Requirement Capability

## Capability Position

Live Requirement负责分析直播类产品需求，定义直播业务中的核心对象、用户角色、直播流程、互动机制、状态变化和权限关系。

该Capability用于支持不同直播产品形态的需求分析，包括：

- 单人直播； 

- 多人连麦； 

- 多人直播； 

- PK类直播； 

- 直播互动能力扩展。 

不负责：

- 具体直播版本方案； 

- 单项目业务规则； 

- 特定玩法参数； 

- RTC底层实现。 

## Analysis Framework

### 核心业务对象

分析直播系统中的核心对象：

- Live Room； 

- Host / Streamer； 

- Audience； 

- Guest / Co\-host； 

- Interaction Object（连麦、PK、互动组件等）； 

- Live Configuration； 

- Live Session状态。 

关注：

- 对象定义； 

- 对象关系； 

- 对象生命周期； 

- 对象之间的权限关系。 

### 用户角色

分析直播场景中的用户角色：

Host：

- 开播； 

- 配置直播； 

- 管理互动用户； 

- 控制直播状态。 

Audience：

- 进入直播； 

- 观看内容； 

- 发起互动； 

- 参与直播能力。 

Guest：

- 加入直播互动； 

- 使用互动能力； 

- 管理自身状态。 

其他角色：

- 根据具体业务补充，例如管理员、运营等。 

### 直播生命周期

分析直播完整流程：

- 开播前配置； 

- 创建直播； 

- 直播中状态管理； 

- 用户进入/退出； 

- 互动能力启停； 

- 直播结束。 

关注：

- 状态变化； 

- 状态触发条件； 

- 状态间转换关系。 

### 直播模式与配置

分析不同直播模式：

- Normal Live； 

- Interactive Live； 

- Multi\-Guest Live； 

- PK Live等。 

关注：

- 模式差异； 

- 配置项； 

- 模式限制； 

- 模式间关系。 

不定义：

- 具体模式数量； 

- 单项目配置参数。 

### 互动能力

分析直播互动功能：

包括但不限于：

- 连麦； 

- 多人互动； 

- PK； 

- 观众参与； 

- 主播控制； 

- 互动入口。 

关注：

- 触发方式； 

- 用户流程； 

- 权限控制； 

- 状态变化。 

### 页面需求

分析直播相关页面：

包括：

- 开播配置页； 

- 直播间页面； 

- 互动管理页面； 

- 主播控制入口； 

- 用户参与入口。 

关注：

- 页面职责； 

- 信息展示； 

- 操作入口； 

- 状态反馈。 

### 权限模型

分析直播中的权限关系：

关注：

- Host权限； 

- Guest权限； 

- Audience权限； 

- 管理角色权限。 

分析：

- 谁可以执行操作； 

- 操作影响范围； 

- 权限限制条件。 

### 数据需求

分析直播业务数据：

包括：

- 用户参与数据； 

- 直播状态数据； 

- 互动数据； 

- 收益相关数据（如涉及）。 

关注：

- 数据展示需求； 

- 数据统计维度； 

- 数据产生条件。 

不负责：

- 数据库设计； 

- 接口实现。 

## Rules

分析直播需求时，优先识别直播业务对象和生命周期，不直接按照页面或功能拆解。 

涉及多人直播、连麦、互动场景时，需要分析： 

- 用户角色关系； 

- 加入/退出流程； 

- 状态变化； 

- 主播控制权限。 

3. 涉及直播模式扩展时，需要区分： 

- 模式能力； 

- 模式配置； 

- 模式生命周期。 

4. 需求信息不足时，仅标记待确认，不推导具体直播规则。
